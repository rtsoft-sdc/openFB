# Модули связи Modbus и OPC UA для IEC 61499

Документация по архитектуре, настройке клиентов, серверов и функциональных блоков ввода-вывода (`BaseIO`).

---

## Modbus

### Архитектура
Система связи Modbus включает три слоя:
* **Менеджер подключения (`MBUS8TCP` / `MBUSLAVE8TCP`)**: Клиент или сервер, обслуживающий до 8 блоков IO.
* **Прослойка связи (`ModbusChannel` / `ModbusChannelAdapter`)**: Обёртка над библиотекой `pymodbus`, транслирующая типы данных IEC (`QX`, `IX` и др.) в функции Modbus.
* **Блоки ввода-вывода (`BaseIO`)**: Непосредственное чтение/запись данных с поддержкой таймингов, а также синхронного и асинхронного режимов.

---

### 1. Настройка клиента `MBUS8TCP`
Блок инициализируется по событию `MAP` и работает в роли Modbus TCP Мастера.

* **Входные параметры:**
  * `QI` (`BOOL`): `True` — подключение и связывание блоков, `False` — разрыв связи.
  * `PARAMS` (`STRING`): Параметры подключения:
    * `Host` — IP-адрес сервера.
    * `Port` — порт (по умолчанию `502`).
    * `Unit ID` — идентификатор устройства (по умолчанию `1`).
  * `IO0` ... `IO7`: Строковые идентификаторы блоков ввода-вывода (`BaseIO`), привязываемых к адаптеру через реестр.
* **Выходные параметры:**
  * `STATUS` (`STRING`): Отображает текущее состояние (`CREATED`, `CONNECTED <ip>:<port>`, `CONNECTION FAILED`, `DISABLED`).

---

### 2. Настройка сервера `MBUSLAVE8TCP`
Блок запускает фоновый Modbus TCP сервер (в отдельном daemon-потоке) и организует локальную карту памяти. Настройка выполняется по событию `MAP`.

* **Входные параметры:**
  * `QI` (`BOOL`): `True` — запуск сервера и выделение памяти, `False` — остановка со статусом `Disabled`.
  * `PARAMS` (`STRING`): Параметры подключения:
    * `Host` — IP-адрес (`0.0.0.0` для всех интерфейсов или `127.0.0.1`).
    * `Port` — порт (`502` или `5020` при отсутствии root-прав).
    * `Unit ID` — идентификатор ведомого устройства (по умолчанию `1`).
  * `IO0` ... `IO7`: Идентификаторы регистрируемых блоков `BaseIO`.
* **Конфигурация памяти:**
  * Сервер выделяет по 65 536 элементов на каждую из четырех областей памяти: `co` (Coils, `0x01`), `di` (Discrete Inputs, `0x01`), `hr` (Holding Registers, `0x01`) и `ir` (Input Registers, `0x01`).
* **Выходные параметры:**
  * `STATUS` (`STRING`): Принимает значения `Created`, `LISTENING on <host>:<port>`, `Disabled / Stopped`, `ERROR: <text>`.

---

### 3. Настройка блоков ввода-вывода (`BaseIO`)
Блоки конфигурируются через параметр `PARAMS` в формате:
`"<Адрес_и_Тип>, <Update_Interval>, <Delay>, <Mode>"`

#### Типы регистров Modbus
| Код | Тип регистра | Доступ | Описание |
| :---: | :--- | :---: | :--- |
| `c` | Coils | R/W | Чтение и запись битов |
| `d` | Discrete Inputs | Read | Только чтение битов |
| `h` | Holding Registers | R/W | Чтение и запись 16-битных регистров |
| `i` | Input Registers | Read | Только чтение 16-битных регистров |

> **Пример адресации:** `h4001` или `h10`. Типы данных IEC 61499 транслируются в операции с регистрами автоматически.

* **Тайминги:**
  * `Update Interval` — частота опроса в секундах (при `0` опрос выполняется каждый цикл без ограничений).
  * `Delay` — задержка старта в секундах для предотвращения пиковых нагрузок на сеть.
* **Режимы работы (`Mode`):**
  * `sync` (Синхронный) — операция чтения/записи блокирует поток до ответа сервера или таймаута.
  * `ind` (Асинхронный) — задачи передаются в `THREAD_POOL`, не блокируя основной цикл IEC 61499 и возвращая последнее известное значение.
* **Логика работы:**
  * **При работе с клиентом:** Блоки отправляют запросы в сеть.
  * **При работе с сервером:** Блок через `execute_read` считывает данные, записанные внешним Мастером в карту памяти `ModbusServerContext`, а через `execute_write` — обновляет локальные ячейки для последующего чтения Мастером.

## OPC UA

### Архитектура
Система связи OPC UA включает три слоя:
* **Менеджер подключения (`OPCUAC_8`)**: Клиент, обслуживающий до 8 блоков IO и управляющий асинхронным event loop в daemon-потоке.
* **Прослойка связи (`OpcUaChannel` / `OpcUaChannelAdapter`)**: Обёртка над библиотекой `asyncua`, транслирующая типы данных, разрешающая пути `NodeId`/`BrowsePath` и управляющая подписками.
* **Блоки ввода-вывода (`BaseIO`)**: Выполняют прямое чтение/запись данных.

---

### 1. Настройка клиента `OPCUAC_8`
Блок инициализируется по событию `MAP` и работает в роли OPC UA Клиента.

* **Входные параметры:**
  * `QI` (`BOOL`): `True` — подключение к OPC UA серверу и запуск асинхронного потока, `False` — остановка потока и разрыв связи со статусом `Disabled`.
  * `PARAMS` (`STRING` / `JSON` / `DICT`): Параметры подключения:
    * `url` — Endpoint URL сервера (по умолчанию `opc.tcp://127.0.0.1:4840`).
    * `mode` — режим работы (`async` / `ind` для асинхронных подписок или `sync` / `req` для прямых запросов).
    * `poll_period` — период подписки/опроса в секундах (по умолчанию `0.1`).
    * `timeout` — таймаут подключения в секундах (по умолчанию `5.0`).
  * `IO0` ... `IO7`: Идентификаторы блоков ввода-вывода (`BaseIO`), привязываемых к адаптеру через реестр.
* **Выходные параметры:**
  * `STATUS` (`STRING`): Отображает текущее состояние (`Created`, `CONNECTED to <url> [<mode> mode]`, `Disabled`, `STOPPED`, `ERROR: <text>`).

---

### 2. Настройка блоков ввода-вывода (`BaseIO`)
Блоки конфигурируются через параметр `PARAMS`, передающий адрес узла OPC UA.

#### Способы адресации
* **`BrowsePath`** (относительный или полный путь): `Objects/MyDevice/Temperature` или `0:Objects/2:MyDevice`.
* **`NodeId`** (идентификатор узла): `ns=2;s=MyVariable`, `2:s=MyVariable` или `ns=1;i=1001`.

> **Примечание:** Адреса автоматически разрешаются в реальные `NodeId` и кэшируются при первом обращении.

#### Маппинг типов данных (IEC 61499 → `ua.VariantType`)
| Тип IEC 61499 | Тип OPC UA Variant |
| :--- | :--- |
| `IX`, `QX` | `Boolean` |
| `IB`, `QB` | `Byte` |
| `IW`, `QW` | `UInt16` |
| `ID`, `QD` | `UInt32` |
| `IL`, `QL` | `UInt64` |
| `IR`, `QR` | `Float` |
| `ILR`, `QLR` | `Double` |
| `IStr`, `QStr`, `IWStr`, `QWStr` | `String` |

#### Режимы работы и логика
* **`ind` / `async` (Асинхронный)**: Создается OPC UA подписка `DataChange Notification`, значения считываются из кэша `SubscriptionHandler` без блокировки цикла IEC 61499.
* **`sync` / `req` (Синхронный)**: Каждое чтение и запись напрямую отправляют запрос к серверу через event loop.
* **Логика операций:**
  * **При чтении (`execute_read`)**: Блок запрашивает актуальное значение из кэша подписки или выполняет прямое чтение с сервера.
  * **При записи (`execute_write`)**: Блок упаковывает значение в объект `ua.Variant` с соответствующим типом данных и отправляет запись на узел OPC UA сервера.
